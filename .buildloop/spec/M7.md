# Spec: M7 Pictr 0.2

**id:** M7   **intent:** .buildloop/intent/M7.md
**policies applied:** global and project CLAUDE.md (Swift 6, no deps, no network, red for
graphics only, never "freed", no em dashes), REVIEW.md
**status:** accepted under the originator's "go wild" scope grant

## Requirements

### Deck
R1. Swipe up (or the heart button) in a decide deck favorites the photo in Photos and records
    a keep. Undo restores the previous decision and, if the photo was not a favorite before,
    unfavorites it. Train decks have no favorite gesture. A failed favorite change shows a
    notice and records nothing.
R2. Share: the toolbar of a decide deck and the viewer bar offer Share for the current item. Sharing
    exports the original file (the edited version when there is one) through
    PHAssetResourceManager, fetching from iCloud only because the user asked.
R3. Shuffle: Today offers a deck of random undecided photos and videos from the whole
    library (deck size from Settings, 25 when "All photos").
R4. On This Day range: Settings picks "This day" or "This week". Week means the seven days
    centred on today's date in each earlier year. Today and the reminder both use it.

### Cleanup
R5. Duplicates: assets with the same media kind, pixel size, capture second, duration and
    exact primary-file byte count (all known) form a group. Burst frames, hidden assets and
    unknown sizes never group. The keeper is the favorite(s), else an edited copy, else the
    lowest ID; it is protected and shown like a Similar keeper. Needs no analysis.
R6. Library insights for the Cleanup window: total items and bytes, a split by kind
    (photos, Live Photos, videos, screenshots, screen recordings) with counts and bytes, bytes
    by year as a chart, the ten largest items (tap opens the viewer), and bytes on this
    iPhone vs iCloud only vs unknown. Estimated sizes are marked.
R7. History CSV: Progress exports confirmed deletes as CSV (date, items, bytes) through the
    share sheet.

### Siri and Shortcuts
R8. App Shortcuts: "Review On This Day", "Shuffle", "Open Cleanup", "Open Ready to Delete"
    open Pictr on that screen; "Ready to Delete count" answers without opening.

## Acceptance criteria
AC1. Zero-warning device build | `xcodebuild ... -destination 'generic/platform=iOS' build` prints BUILD SUCCEEDED and no `warning:` lines from Pictr sources
AC2. Unit tests pass, including new ones | `xcodebuild ... -only-testing:PictrTests test` TEST SUCCEEDED
AC3. Duplicate grouping rules | `DuplicateTests`: groups exact matches; ignores bursts, hidden, unknown sizes, different seconds/dims/bytes; keeper favorite > edited > lowest ID
AC4. Week windows | `OnThisDayTests`: week range yields 7-day windows centred on the date per earlier year; Feb 29 handled
AC5. Insights math | `InsightsTests`: totals equal sums, kinds partition the items, years sum to total, top-N ordered by bytes, availability split sums to total
AC6. CSV | `ProgressTests`: header plus one row per applied entry, ISO dates
AC7. Shuffle sampling | `ShuffleTests`: excludes decided IDs, respects count, no duplicates
AC8. Deck favorite bookkeeping | `ReviewTests`: favorite step records keep; undo restores
AC9. No network code | the CLAUDE.md grep prints nothing
AC10. No "freed", no em dashes in new UI copy | `grep -rni freed Pictr` and a grep for U+2014 over Pictr both print nothing
AC11. Device walkthrough still passes and reaches the new screens | `DeviceSmokeTests` on POSEIDON

## Ordering surface
state-machine: the deck's favorite + undo interacts with an async Photos write. The record
is written only after the write succeeds, and the deck ignores swipes, buttons and undo while
the write is in flight. Undo of a favorite step restores the decision at once and unfavorites
in the background; if that write fails the photo stays a favorite (protected, never lost).

## Rejected alternatives
- Duplicates by feature print across the whole library: O(n^2) Vision work, device only,
  and Similar shots already covers visual near-duplicates within ten minutes.
- Sharing the on-screen image: loses resolution and metadata; users expect the original.
- A widget now: needs an App Group and a new bundle ID on the developer account.
