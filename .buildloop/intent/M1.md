# Intent: M1, the first working cleanup loop

**id:** M1   **originator:** Zac   **date:** 2026-11-13

## The ask (originator's words, condensed)
An on-device photo cleanup app for iOS. Inspirations: GetSorted (swipe to delete/keep,
daily batches, duplicates/screenshots/blurry) and PhotoTriage (on-device preference
learning, "Maybe Delete" buckets with reasons, never auto-deletes).

M1: permission flow, fetch the last 30 days, size every asset off the main actor,
bucket on cheap signals (Screenshots, Burst extras, Large videos >= 100 MB), a bucket
list with counts/bytes/estimate markers, a bucket detail grid with a single
"Delete N (X GB)" commit per bucket through Apple's system confirmation, change-observer
reconciliation, and an honest space summary.

## Why
Cleaner apps lie about space. Honest space math is a core product principle: deleted
assets sit in Recently Deleted for 30 days, and with iCloud Optimize Storage the device
may gain little. Never call a number "freed".

## Constraints
- On-device only. No networking, no analytics, no uploads. Privacy label: Data Not Collected.
- Never auto-delete. One system-confirmed batch per bucket. Cancel is a normal outcome.
- iOS 26.0, Swift 6 strict concurrency, @Observable, no third-party dependencies.
- PhotoKit behind small protocols; main actor for UI only.
- Never download iCloud originals. Favorites and hidden excluded everywhere.
- Never run a delete against the real library as a test without explicit say-so.

## Out of scope
Swipe review (M2), Vision buckets (M3), SwiftData cache (M4), preference learning (M5),
background tasks, re-encoding, monetization.
